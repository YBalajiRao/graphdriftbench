## Part A — Environment setup (human + agent)

### A1. Where to run: WSL2 (recommended)

PyTorch Geometric, `py-tgb` and their compiled extras are far easier on Linux. Your machine (Windows 11, RTX 3070 8 GB, 32 GB RAM) supports WSL2 with CUDA.

```powershell
# PowerShell (Admin), once — skip if Ubuntu on WSL2 is already installed
wsl --install -d Ubuntu
```

Inside Ubuntu:

```bash
nvidia-smi                      # must show the RTX 3070 (the Windows driver provides CUDA to WSL)
mkdir -p ~/research && cd ~/research
git clone <your-empty-github-repo-url> graphdriftbench   # or: mkdir graphdriftbench && cd graphdriftbench && git init
```

Keep the repo inside the WSL filesystem (`~/research/...`), not on `/mnt/d/...` — file I/O across the Windows boundary is much slower. Put large datasets on D: only if space requires it (`/mnt/d/tgb_data`) and point `TGB_DATA_DIR`/config to it.

### A2. Install Claude Code [check docs]

```bash
# inside WSL (Linux installer)
curl -fsSL https://claude.ai/install.sh | bash
# alternative: npm install -g @anthropic-ai/claude-code
cd ~/research/graphdriftbench && claude
```

(Native Windows alternative from PowerShell: `irm https://claude.ai/install.ps1 | iex` — then run `claude` in `D:\research\graphdriftbench`. WSL is still preferred for this project.)

### A3. Python environment (agent does this, with your approval)


## Part B — Make Claude Code good at this project

### B1. `CLAUDE.md` (repo root) — create exactly this

```markdown
# Project: GraphDriftBench / CSEE (PhD Paper 1)

Source of truth: docs/Paper1_Blueprint.md. Paper 2/3 ideas (docs/Paper2_Paper3_Roadmap.md) are OUT OF SCOPE — do not implement world models, forecasting, CVaR or healthcare.

## Task
Continual learning for continuous-time dynamic link prediction under drift. Four drift types from P(V)P(A|V)P(X|A,V)P(Y|A,X,V): gamma = node turnover, beta = topology, alpha = features, delta = relational-semantic (link rule). Detector = 4 tests + CUSUM + Bonferroni. Memory = k-core ego-nets, refreshed only on alarms, policy conditioned on drift type.

## Hard rules
- Never invent, round or hand-edit results. Every number in a table/figure/paper comes from results/*.csv produced by a script in scripts/. Tables are generated by scripts/make_tables.py.
- Metrics: AF = mean_i( max_{l in [i, T-1]} A[l,i] - A[T,i] ); BWT = mean_i( A[T,i] - A[i,i] ). They are different; tests enforce this.
- The learner must never see injection times, injection types or evaluation segment boundaries.
- All baselines run under the same protocol, backbone, memory budget, negatives and seeds. Never copy numbers from other papers into our tables.
- Seeds: 0-4. Set torch/numpy/random seeds and log them. Deterministic flags where feasible.
- GPU: RTX 3070, 8 GB. Default to small batch/memory dims; check peak memory; never assume multi-GPU.
- Citations (supervisor rule): NO preprints (no arXiv links/refs). Only DOI or peer-reviewed proceedings records. Mark anything unverified as [verify].
- Ask before: installing system packages, deleting data/results, changing anything in docs/, or changing the evaluation protocol.

## Layout
src/gdb/{synth,inject,data,detect,memory,models,cl,eval,utils}; configs/ (Hydra); scripts/; tests/; results/; docs/

## Commands
- tests: `pytest -q`  (fast subset: `pytest -q -m "not slow"`)
- lint/format: `ruff check --fix . && ruff format .`
- run: `python scripts/run.py experiment=<name> seed=<s>`

## Style
Type hints, docstrings with the math (LaTeX) for every statistic and metric, small pure functions, no notebooks in src/.
```

4. **`citation-policy`** — *"Use when writing related work, references or BibTeX."* Body: no preprints; DOI required; check every DOI resolves to the claimed title/venue/year; keep `docs/references.bib` as the single source; flag in-press 2026/2027 volumes correctly.

### B3. Subagents (`.claude/agents/<name>.md`)

- **`code-reviewer`** — reviews diffs for correctness, leakage (does the learner see injection info or future events?), seed handling, GPU memory. Tools: Read, Grep, Glob, Bash (read-only commands).
- **`metrics-auditor`** — re-derives every metric/statistic from the Blueprint formulas and writes failing tests if the code disagrees (AF vs BWT, MRR with TGB negatives, CUSUM threshold calibration, detection delay with tolerance).
- **`experiment-auditor`** — before any table is made: checks that all methods share budget/seeds/negatives/backbone, that no run is missing, and that the numbers in the tables match `results/*.csv`.

## Part C — Step 1 specification (do not start until Part A/B are done and approved)

### Goal
A continuous-time dynamic SBM generator with type-pure drift injectors (α, β, γ, δ), mixed and recurring drifts, and ground-truth annotations — the core of GraphDriftBench.

### Files
```
src/gdb/synth/dsbm.py          # DSBMConfig, generate_stream()
src/gdb/synth/injectors.py     # inject_alpha/beta/gamma/delta, DriftEvent, DriftSchedule
src/gdb/synth/schedules.py     # abrupt, gradual (ramp), mixed, recurring A->B->A
src/gdb/data/stream.py         # EventStream dataclass (src, dst, t, edge_feat, node_feat, node_ids) + PyG TemporalData export
src/gdb/utils/graph_stats.py   # degree dist, KPM density of states, k-core numbers (reused later by detector)
configs/synth/*.yaml
tests/test_dsbm.py, tests/test_injectors.py, tests/test_purity.py
scripts/gen_synth.py           # writes data/synth/<name>/{stream.pt, drift_truth.csv, config.yaml}
```

### Generator (Blueprint §6.1)
- Parameters: `N`, `K`, block sizes, block intensity matrix `B`, node-feature means per block + `sigma`, homophily weight `beta_h`, edge-mark dim + distribution, horizon `T_end`, optional recency term, `seed`.
- Event intensity for pair (u, v): `B[z_u, z_v] * exp(beta_h * cos(x_u, x_v))`; simulate with block-level Poisson thinning so the cost is O(#events), not O(N²).
- Edge marks independent of endpoints (keeps δ pure).

### Injectors (applied from time `tau` onward, magnitude `eps`)
- `inject_alpha`: shift the edge-mark mean by `eps * d` (unit vector d). Structure untouched.
- `inject_beta`: `B <- (1-eps) B + eps B'` (merge/split/densify presets). Marks and `beta_h` untouched.
- `inject_gamma`: replace a fraction `eps` of nodes with fresh IDs drawn from the same block/feature law (old IDs stop emitting events).
- `inject_delta`: `B <- P B Pᵀ` for a permutation P over blocks with equal size and equal row sums, and/or `beta_h <- -beta_h`.
- Each injection appends `(tau, type, eps, params)` to `drift_truth.csv`. Mixed = list of simultaneous injections; recurring = schedule that restores the original law.

### Acceptance tests
1. Stationary stream: event counts per block pair within 3σ of expectation (Poisson).
2. Reproducibility: same seed → identical stream (hash equality).
3. **Purity** (on windows just before vs after `tau`, 20 seeds):
   - γ and δ: degree-distribution KS test p > 0.05 and KPM-DoS Wasserstein distance within the 95% stationary null band; edge-mark MMD within null band.
   - α: degree distribution and DoS within null band; mark MMD significant.
   - β: DoS distance significant; mark MMD within null band.
   - δ: block-pair event-count matrix changes (permuted) while its multiset of entries is unchanged.
4. `drift_truth.csv` matches the configured schedule exactly.
5. Export to PyG `TemporalData` works, and a 10-epoch TGN smoke run on a small synthetic stream fits in < 2 GB VRAM.
6. Runtime: 1M events generated in < 2 minutes on CPU.

### Deliverable back to the human
`docs/progress/step-1.md` with: the config presets, the purity-test table (pass/fail per type), runtime, and any deviations from the Blueprint with reasons.
